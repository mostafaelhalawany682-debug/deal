# Deal — نسخة Vercel + Supabase

سوق يربط صناع المحتوى الصغار بمحلات وبراندات مدينتهم، مع خدمات متكاملة (إدارة إعلانات ممولة، حلول مشاكل الحسابات)، وحجوزات P2P محمية بـ«ضمان Deal».

هذه النسخة مهيأة للنشر على **Vercel** (serverless) مع قاعدة بيانات **PostgreSQL على Supabase** — نفس منطق العمل وقواعد النسخة المستقلة تماماً، مع استبدال SQLite بـ Postgres حتى تبقى البيانات دائمة ولا تُصفَّر أبداً. السوق يبدأ فارغاً — لا بيانات وهمية.

## متغيرات البيئة (فقط اثنان)

| المتغير | المعنى |
|---|---|
| `DATABASE_URL` | رابط اتصال PostgreSQL من Supabase (انظر خطوات Supabase بالأسفل). **سرّي — لا يوضع في الكود أبداً** |
| `COMMISSION_PHONE` | رقم محفظة عمولات Deal (فودافون كاش/إنستاباي). يبقى في الخادم فقط ولا يظهر إلا للعميل الدافع داخل خطوة دفع العمولة في حجز مؤكد |

(`PORT` للتشغيل المحلي فقط — Vercel يدير المنفذ بنفسه.)

## التشغيل محلياً

```bash
cp .env.example .env   # ضع DATABASE_URL وCOMMISSION_PHONE
npm install
npm start              # يفتح على http://localhost:3000
```

الجداول تُنشأ تلقائياً عند أول تشغيل (`CREATE TABLE IF NOT EXISTS`) — لا خطوات يدوية في قاعدة البيانات.
أول حساب يُسجَّل يصبح تلقائياً **مؤسس المنصة** (شارة «مؤسس Deal» + لوحة المالك)، وأول 100 صانع «أعضاء مؤسسون».

## خطوة 1 — إنشاء مشروع Supabase والحصول على DATABASE_URL

1. من [supabase.com](https://supabase.com) أنشئ مشروعاً جديداً (اختر كلمة سر قوية لقاعدة البيانات واحتفظ بها).
2. بعد جاهزية المشروع: **Settings ← Database ← Connection string**.
3. انسخ رابط الاتصال. للنشر على Vercel استخدم رابط **Transaction Pooler** (فيه `pooler.supabase.com` والمنفذ **6543**) — لأن كل نسخة serverless تفتح اتصالاتها الخاصة، والـ Pooler يمنع نفاد الاتصالات. (الرابط المباشر على المنفذ 5432 يعمل أيضاً، لكن الـ Pooler هو الاختيار الصحيح لـ Vercel.)
4. ضع الرابط كاملاً (مع كلمة السر بدل `<PASSWORD>`) في متغير البيئة `DATABASE_URL`.

قاعدة الإنتاج **تبدأ فارغة**: الجداول تُنشأ عند أول طلب، وأول مستخدم يسجل هو مؤسس المنصة.

## خطوة 2 — النشر على Vercel

1. ارفع هذا المجلد إلى مستودع GitHub خاص بك.
2. في [vercel.com](https://vercel.com): **Add New ← Project** واختر المستودع (الإعدادات الافتراضية تكفي — لا Framework).
3. قبل أول Deploy (أو بعده من **Settings ← Environment Variables**) أضف المتغيرين: `DATABASE_URL` و`COMMISSION_PHONE`.
4. Deploy — سيصلك رابط عام شكله `https://deal-xxxx.vercel.app` يفتح عند أي حد، ويتثبت على الموبايل (PWA) من زر «ثبّت Deal».
5. لاحقاً اربط نطاقك الخاص (مثل trydeal.app) من **Settings ← Domains**.

كيف يعمل النشر: الواجهة الثابتة تُخدَم من `public/` مباشرة، وكل مسارات `/api/*` تُوجَّه (عبر `vercel.json`) إلى دالة serverless واحدة في `api/index.js` تصدّر تطبيق Express نفسه.

## قواعد العمل (مطابقة للنسخة المستقلة)

- **العمولة أولاً:** عمولة Deal ‏10% من قيمة الحجز يدفعها العميل مباشرة لحساب عمولات التطبيق قبل أي مليم للصانع، وتتأكد تلقائياً عند تسجيل مرجع العملية (نافذة إدارة 48 ساعة لرفض مرجع خاطئ تفتح نزاعاً). بعدها: عربون نصف صافي الصانع (45%) ← تنفيذ ← باقي 45% بعد إثبات التنفيذ وتأكيد الاستلام. إجمالي العميل = السعر المعلن دائماً.
- **إثبات التنفيذ:** رابط علني يتحقق منه الخادم (HTTP 200) ويُختم بوقته؛ سكوت العميل 48 ساعة بعد إثبات سليم = تأكيد استلام تلقائي. الرابط يُحفظ في معرض أعمال الصانع بعد اكتمال الصفقة.
- **التقييمات** بعد اكتمال القبض فقط، مرة واحدة لكل طرف، بلا تعديل.
- **عقوبات تلقائية:** 3 تقييمات سلبية = تنبيه، 5 = تعليق + تجميد الرصيد داخل التطبيق ومنع حجوزات جديدة؛ الحظر وفك التجميد بقرار المالك.
- **توثيق آلي:** كود ملكية يضعه الصانع في بايو حسابه العلني، والخادم يقرأ الصفحة ويتحقق من الكود وتطابق الاسم: قبول فوري (شارة ذهبية + Boost أسبوع + «رائد المدينة» لأول موثق بمدينة+مجال) أو رفض مسبب أو «مراجعة استثنائية» يبت فيها المالك.
- **شارات إنجاز** تُحسب من السجل فقط (إتمام مثالي، الأعلى تقييماً، تنفيذ سريع، صانع صاعد، سفير Deal، مخضرم) مع كسب/سحب وتنبيه، وخزانة شارات بالملف مع تقدم كل شارة.
  - ملحوظة: شارة «سفير Deal» معرّفة ومحسوبة البنية، لكن عدّاد الدعوات يحتاج تفعيل أكواد الدعوة (دالة `invitedDone` في `server/index.js`) — خطاف جاهز للتفعيل كما في النسخة المستقلة.
- **فرص ليك:** مطابقة تلقائية (مدينة + مجال + ميزانية مناسبة لحدّك الأدنى) بنسبة وأسباب، من طلبات المحلات وحملات البراندات؛ قبول البراند لتقديم صانع ينشئ حجزاً عادياً.
- **تنبيهات** داخل التطبيق (جرس بعدّاد) + زر «نبّه الصانع واتساب» برسالة جاهزة.
- **لوحة مالك** للمؤسس فقط: عمولات يوم/شهر/إجمالي من سجلات العمولة الفعلية، نزاعات وحلّها، مراجعات استثنائية، حسابات معاقبة وفك تجميدها، ورفض مراجع عمولة خاطئة.
- **إحصائيات صانع:** مشاهدات ملف حقيقية (مشاهدة النفس لا تُحسب)، فرص، معدل تحويل، أرباح بالشهر.

## قيود Vercel serverless ومعالجتها

- **مدة تنفيذ الدالة:** مضبوطة على 30 ثانية كحد أقصى في `vercel.json` (`maxDuration`). أطول عملية عندنا هي جلب صفحة خارجية للتوثيق/إثبات التنفيذ — خُفّض مهلة الجلب إلى **8 ثوانٍ** حتى تبقى كل الطلبات داخل السقف بهامش آمن.
- **اتصالات قاعدة البيانات:** كل نسخة serverless تنشئ تجميعة اتصالات خاصة بها — لذلك التجميعة صغيرة (`max: 5` لكل نسخة) ويُنصح بشدة برابط **Transaction Pooler** من Supabase (منفذ 6543) بدل الاتصال المباشر.
- **بدء التشغيل (Cold Start):** إنشاء الجداول يعمل مرة واحدة عند أول طلب لكل نسخة (`CREATE TABLE IF NOT EXISTS` — آمن وسريع عند التكرار).
- **نظام الملفات المؤقت:** لا نعتمد عليه إطلاقاً في هذه النسخة — كل الحالة في Postgres، وهذا أصل التكييف.
- **أخطاء قاعدة البيانات:** معالج أخطاء أخير يحوّل أي خطأ إلى رد `500` JSON بدل تعليق الطلب (مع Express 5 تُمرَّر أخطاء الدوال غير المتزامنة إليه تلقائياً).

## الاختبار

```bash
npm test
```

يشغّل 36 فحصاً من الطرف للطرف (الـ35 فحصاً الأصلية في `TESTING.md` + فحص مدخل Vercel) ضد PostgreSQL حقيقي مضمّن في بيئة الاختبار فقط (`embedded-postgres` في devDependencies — لا يدخل اعتماديات الإنتاج). النتائج موثقة في `TESTING-VERCEL.md`.

## بنية المشروع

```
server/
  db.js        طبقة PostgreSQL (pg Pool + إنشاء الجداول + واجهة prepare/get/all/run غير المتزامنة)
  index.js     كل واجهات API ومنطق العمل (يصدّر تطبيق Express؛ يستمع فقط عند التشغيل المباشر)
api/
  index.js     مدخل Vercel serverless (يصدّر التطبيق)
public/        واجهة SPA (عربية RTL) + PWA + الأيقونات — تُخدَم ثابتة
vercel.json    توجيه /api/* إلى الدالة + maxDuration
tests/         سكربت الاختبارات
```
